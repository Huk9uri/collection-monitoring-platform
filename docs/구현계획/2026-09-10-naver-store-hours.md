# 네이버 영업시간 모니터링 연동 구현 계획

승인 설계: 크롤러의 독립 감사 기록과 플랫폼 SELECT 전용 어댑터를 사용한다.

1. 크롤러 계측: 예약 시작/종료 및 검증된 브랜드 dry-run/Apply snapshot을 정제한다. UUID5로 부모/브랜드 ID를 고정하며 업무 트랜잭션과 별도 연결에서 멱등 저장한다. 사전 점검 전용 실행을 명시하고 명시적 호스트 시간대로 UTC 변환한다.
2. 감사 DDL: 전용 실행 테이블에 정제된 브랜드 결과와 단계 JSON을 저장한다. 원문 오류와 경로를 제외하고 DBA용 제약조건/최소 권한 검증 SQL을 제공한다.
3. 플랫폼: naver-store-hours 어댑터, 선택적 연결 설정, 주간 일정 정책을 추가한다. 공통 실행 모델에 원본 상태, 부모 UUID, 실행 종류, 검토/실패/반영/커버리지 지표를 추가한다. 기존 어댑터 계약은 기본값으로 호환한다.
4. 웹: 공통 schema와 상세에서 새 지표를 표시한다. 기존 브랜드 필터/수동 새로고침을 재사용한다.
5. 비운영 검증: 먼저 fixture 테스트 실패를 확인한 뒤 구현한다. 상태/품질 분리, 확정 Apply, null, 시간대, 멱등성, 장애 격리, 조회 전용 SQL 및 UI를 검증하고 전체 API/웹/lint/typecheck/build와 영업시간 회귀를 실행한다.
6. 운영 문서: DDL 검토, 별도 계정, 환경변수, 첫 정규 회차 대조, 배포/롤백 및 관측 한계를 한국어로 작성한다.

운영 DDL 적용, 서버 배포, 예약 변경, 네이버 접속, 실제 크롤러 실행, 메일 발송은 금지한다. 기존 사용자 변경을 보존한다. 일정 미확인 시 누락/지연 판정을 비활성화한다.
## 완료 기록

1~6단계를 구현·검증했다. API 222개, 웹 85개, 영업시간 크롤러 485개 테스트가 통과했고 웹 lint/typecheck/build도 통과했다. 운영 적용은 수행하지 않았다.

재검토 결정: 단일 단계 최댓값 대신 최종 worker/attempt별 매장 집계를 저장하여 재시도 관계를 보존했다. 과거 worker 시각이 없으면 parent-window 근거를 명시한다. 전부 실패한 Apply의 빈 집합을 성공 반영으로 해석하지 않으며 성공 매장 수는 dry-run 후보가 아닌 확인된 Apply를 사용한다. preflight-only는 실행 이력에 종류를 표시하되 수집 KPI/신선도에서는 제외한다.
