# 데이터 수집 모니터링 플랫폼 구현 계획

> **에이전트 작업자 필수 사항:** 작업 단위 구현에는
> `superpowers:subagent-driven-development`를 사용한다. 각 작업은 테스트 우선,
> 구현, 검증, 커밋, 요구사항/품질 검토 순으로 완료한다.

**목표:** FC다움과 HMR 수집의 API 호출, DB 적재, 신선도를 읽기 전용으로
조회하고 향후 수집기를 어댑터로 추가할 수 있는 독립 플랫폼을 구축한다.

**아키텍처:** `apps/api`의 FastAPI가 수집기별 DB 어댑터를 공통 계약으로
정규화하고, `apps/web`의 React 앱은 이 계약만 소비한다. FC다움 수집기는 별도
저장소에서 감사 이력을 추가하고 HMR은 기존 감사 테이블을 유지한다.

**기술 스택:** Python 3.12, FastAPI, Pydantic Settings, pyodbc, pytest,
React 19, TypeScript, Vite, Tailwind CSS, shadcn/ui, TanStack Query,
TanStack Router, TanStack Table, Zod, Vitest

**설계 문서:** `docs/설계/2026-09-08-데이터-수집-모니터링-플랫폼.md`

## 전역 제약사항

- 설계, 구현 계획, 운영 문서는 항상 한국어로 작성한다.
- MVP에는 수집 실행이나 DB 변경 API를 추가하지 않는다.
- `PARTIAL_FAILED`는 `WARNING`이 아닌 장애 등급이며 `부분 실패`로 표시한다.
- API 시각은 UTC ISO 8601, 화면 시각은 Asia/Seoul 기준이다.
- DB 계정은 데이터 소스별 읽기 전용 계정을 사용한다.
- 비밀정보, 원문 응답, SQL 원문, 원문 예외를 저장하거나 공개하지 않는다.
- 웹은 모니터링 기능만 포함하며 기존 관리자 예제 기능을 복제하지 않는다.
