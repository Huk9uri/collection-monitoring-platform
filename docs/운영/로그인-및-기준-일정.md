# 로그인 및 모니터링 기준 일정 운영

## 현재 구현

아이디·비밀번호 로그인, 쿠키 세션 복구, 로그아웃, 비밀번호 변경 API와 계정 생성·
초기화 CLI를 제공한다. viewer는 모니터링과 기준 일정을 조회하고 admin은 일정
전체 교체와 변경 이력 조회를 추가로 수행한다. 기존 operator 의미는 유지한다.

별도 로그인 운영 정책을 두지 않는다는 사용자 지시를 반영했다. 별도 실패 제한·
비밀번호 정책 환경변수를 요구하지 않는다. 최소 길이 강제는 없으며 비어 있지 않은
최대 1024자 비밀번호를 Argon2id로 저장한다. 반복 시도 방어(5회·15분)와 세션
유휴 8시간·절대 24시간은 내부 기본값이다. 세션 원문과 CSRF 원문은 DB에 저장하지
않으며 CSRF는 브라우저 메모리에만 둔다.

## 배포 설정

기존 수집 연결과 별도로 다음 값을 설정한다.

- `MONITORING_CONTROL_CONNECTION_STRING`: 제어 테이블 최소 권한 계정 연결
- `MONITORING_CORS_ORIGINS`: 정확한 HTTPS 웹 Origin, 쉼표 구분
- `MONITORING_ALLOWED_HOSTS`: API Host 이름, 쉼표 구분, 운영에서는 와일드카드 금지
- `MONITORING_PRODUCTION=true`: HTTP 리다이렉트, API 문서 비활성화
- 웹의 `VITE_MONITORING_API_URL`: API 주소, 같은 Origin의 경우 생략 가능

웹과 API는 같은 사이트의 HTTPS로 제공한다. Secure·SameSite=Lax 쿠키를 사용하므로
서로 다른 사이트로 배포하면 로그인 세션이 전송되지 않는다. 로컬 개발도 로그인은
HTTPS 역방향 프록시를 사용한다. 프록시는 `/api/` 및 `/health/`를 API로 전달하고
그 외 앱 경로는 웹의 index.html로 전달해야 한다. 웹에서 직접 URL로 들어간
`/login`, `/settings/schedules`도 이 fallback 대상이다.

TLS 종료 프록시 뒤에서는 Uvicorn이 해당 프록시 주소만 신뢰하도록 forwarded
설정을 구성한다. 임의 외부 요청의 전달 헤더를 신뢰하지 않는다. 인증 요청에는
Origin, 세션, 필요한 역할, 세션 귀속 CSRF를 함께 검증한다. CSRF 복구 GET은
Origin 또는 같은 웹 Origin의 Referer가 필요하므로 웹의 referrer policy는
`strict-origin-when-cross-origin`을 권장한다.

`/health/live`는 공개 생존 검사이고 `/health/ready`는 관리자 인증을 요구한다.
인증 DB 장애는 보호 API를 503으로 차단한다.

## 계정 관리

프로젝트 루트에서 실행한다. 비밀번호는 명령행 인자로 받지 않는다.

```powershell
apps/api/.venv/Scripts/python.exe -m monitoring_api.control_cli verify
apps/api/.venv/Scripts/python.exe -m monitoring_api.control_cli create-user --role admin
apps/api/.venv/Scripts/python.exe -m monitoring_api.control_cli create-user --role viewer
apps/api/.venv/Scripts/python.exe -m monitoring_api.control_cli reset-password
```

사용자가 준비한 `MONITORING_ADMIN_USERNAME`, `MONITORING_ADMIN_PASSWORD`는
`create-user --from-env-once`에서만 읽는다. 앱 런타임은 이 값을 사용하지 않는다.
동일 계정이 있으면 덮어쓰지 않는다. 초기 생성 후 `.env`의 ADMIN_PASSWORD는
운영자가 제거한다. 비밀번호 초기화는 기존 세션을 모두 폐기하고 감사에 기록한다.

## 기준 일정

DB 정책은 수집기 단위 완전한 snapshot이다. 환경 설정과 필드별 혼합을 하지 않는다.
DB에 정책이 없으면 기존 환경 판정을 유지한다. 환경에 유예·귀속 범위가 없는 경우
화면에서도 빈 값으로 표시하며 관리자가 실제 기준을 입력해야 DB 저장이 가능하다.
조회 캐시는 60초이고 저장한 프로세스의 캐시는 즉시 무효화한다. DB 장애 시 마지막
정상 snapshot 또는 환경 설정을 사용하며 카드와 일정 화면에 출처·경고를 표시한다.

요일·시각·신선도 SLA·사유를 검증하고 rowversion 충돌은 409로 반환한다. 사용자
입력은 유지하고 최신 정책을 비교한 뒤 다시 저장한다. 정책과 감사 이력은 같은
트랜잭션이며 감사 실패 시 전체 롤백한다. 화면의 판정은 현재 정책 기준이며 저장된
과거 canonical 상태나 실제 작업 스케줄러를 변경하지 않는다.

신규 정책의 신선도 데이터셋은 어댑터별 등록 목록으로 제한한다. SmartPlace는
현재 데이터셋 신선도 목록이 없으므로 일정과 실행시간 기준만 제공한다.
일광 절약 시간으로 존재하지 않는 현지 시각은 건너뛰고 중복되는 시각은 첫 회차로
해석한다. 과거 실행 건수 KPI는 저장된 상태 집계를 유지한다.

## 실제 검증 기록 및 배포 전 확인

2026-09-14에 사용자 제공 연결로 7개 테이블 존재·조회 권한을 확인했다. 초기 admin
생성, 해시 일치, 실제 로그인·세션 조회·로그아웃 폐기 smoke를 통과했다.
smoke는 인증 테이블에 세션·감사 기록만 생성했고 해당 세션은 폐기했다.

최종 자동 검증: API pytest 261개, 웹 Vitest 93개 통과. 웹 typecheck·lint·build를
실행한다. 기존 수집기 작업 변경은 함께 보존했으며 작업 결과는 미커밋 상태다.

현재 제공 연결은 CREATE TABLE과 데이터베이스 CONTROL 권한이 있다. 운영 전
별도 최소 권한 계정으로 교체해야 한다. 실제 업무 테이블 DML 권한 부재와 HTTPS
도메인·프록시 경계는 아직 검증하지 않았다. 실제 정책은 운영 일정 확인 후 화면에서
명시적으로 저장하며 임의의 일정을 DB에 초기 주입하지 않는다.
