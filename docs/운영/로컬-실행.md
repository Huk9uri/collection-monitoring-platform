# 로컬 실행

## 1. 실행 원칙

이 플랫폼은 FC다움과 HMR의 감사·업무 테이블을 조회하는 모니터링 전용
애플리케이션이다. API 시작 시 DB 연결을 열거나 수집 작업을 실행하지 않는다.
연결은 readiness 또는 모니터링 GET 요청 시 열리고 조회가 끝나면 닫힌다.

MVP에는 수집 실행·재실행·삭제 기능이 없다. 웹도 자동 polling 없이 최초 조회와
사용자의 `새로고침` 동작으로만 API를 다시 호출한다. 로그인은 아직 구현하지
않았으며, 익명 사용자를 `viewer`로 취급하는 인증·역할 설계 경계만 있다. 따라서
로컬 외 환경에서는 사내망, 방화벽, reverse proxy 접근 제어를 반드시 함께
사용한다.

## 2. 준비물

- Node.js 22.13.0 이상
- Python 3.12 64비트
- Microsoft ODBC Driver 18 for SQL Server
- FC다움 DB와 HMR DB에 각각 발급한 SELECT 전용 계정

적재 계정, 수집기 `.env`, 다른 프로젝트의 자격 증명을 재사용하지 않는다.
FC다움과 HMR 계정도 서로 분리한다. 각 계정에는 필요한 감사·신선도 테이블과
시스템 카탈로그 조회 권한만 주고 DDL/DML 권한은 주지 않는다.

## 3. 의존성 설치

저장소 루트에서 실행한다.

```powershell
npm install
py -3.12 -m venv apps/api/.venv
apps/api/.venv/Scripts/python.exe -m pip install -e "apps/api[test]"
```

## 4. 환경변수

루트의 `.env.example`은 키와 형식만 제공한다. 실제 값은 커밋하지 말고 로컬
`.env` 또는 운영 비밀 저장소에 둔다.

| 변수 | 필수 여부 | 설명 |
| --- | --- | --- |
| `MONITORING_FCDAUM_CONNECTION_STRING` | 소스별 선택 | FC다움 DB SELECT 전용 ODBC 연결 문자열 |
| `MONITORING_HMR_CONNECTION_STRING` | 소스별 선택 | HMR DB SELECT 전용 ODBC 연결 문자열 |
| `MONITORING_CORS_ORIGINS` | 브라우저 분리 배포 시 필수 | 허용할 웹 Origin. 스킴·호스트·포트를 포함하고 여러 값은 쉼표로 구분 |
| `VITE_MONITORING_API_URL` | 웹 필수 | 브라우저가 호출할 API 기준 URL |

연결 문자열에는 `ApplicationIntent=ReadOnly`를 명시한다. 앱도 누락 시 이를
추가하고 `ReadWrite` 값을 거부하지만, 이것은 DB 권한을 대신하지 않는다.

```dotenv
MONITORING_FCDAUM_CONNECTION_STRING=Driver={ODBC Driver 18 for SQL Server};Server=<FCDAUM_SQLSERVER>;Database=<FCDAUM_DATABASE>;UID=<FCDAUM_READONLY_USER>;PWD=<SECRET_FROM_SECRET_STORE>;Encrypt=yes;TrustServerCertificate=no;ApplicationIntent=ReadOnly
MONITORING_HMR_CONNECTION_STRING=Driver={ODBC Driver 18 for SQL Server};Server=<HMR_SQLSERVER>;Database=<HMR_DATABASE>;UID=<HMR_READONLY_USER>;PWD=<SECRET_FROM_SECRET_STORE>;Encrypt=yes;TrustServerCertificate=no;ApplicationIntent=ReadOnly
MONITORING_CORS_ORIGINS=http://localhost:5173
VITE_MONITORING_API_URL=http://localhost:8000
```

두 연결 변수 중 하나만 설정하면 해당 소스만 등록된다. 둘 다 없으면 API는
기동되지만 readiness는 503이다. Pydantic 설정의 연결 문자열 필드는 마스킹되며,
API 오류 응답에는 연결 문자열, SQL 원문, 원문 예외를 포함하지 않는다.

API를 저장소 루트에서 실행할 때는 루트 `.env`를 읽는다. Vite는
`apps/web`을 환경 루트로 사용하므로 웹 URL은 다음 중 하나로 전달한다.

```powershell
# 방법 1: 현재 셸에만 주입
$env:VITE_MONITORING_API_URL = "http://localhost:8000"

# 방법 2: apps/web/.env.local에 VITE_MONITORING_API_URL 한 줄 저장
```

`.env.local`도 실제 배포 주소가 들어갈 수 있으므로 커밋하지 않는다.

## 5. FC다움 감사 테이블 준비

FC다움 모니터링을 처음 연결할 때만 다음 순서를 지킨다.

1. DBA 또는 승인된 마이그레이션 계정으로 대상 DB와 `dbo` 스키마를 확인한다.
2. `C:\workspace\fcdaum_crawling\sql\080_create_collection_audit_tables.sql`을
   적용한다. 이 파일은 DDL이므로 모니터링 SELECT 전용 계정으로 실행하지 않는다.
3. `C:\workspace\fcdaum_crawling\sql\085_verify_collection_audit_tables.sql`을
   실행한다. 085는 테이블·컬럼·인덱스·제약조건·최근 이력만 읽는 SELECT-only
   검증이다.
4. 두 감사 테이블과 PK·인덱스, 예상 컬럼이 모두 조회되는지 확인한다.
5. 그 뒤 FC다움 SELECT 전용 계정으로 085를 다시 실행해 실제 조회 권한을
   검증하고 `MONITORING_FCDAUM_CONNECTION_STRING`을 주입한다.

080 적용과 085 확인 과정에서 수집기는 실행하지 않는다. HMR은 기존
`CHANNEL_COLLECTION_RUN`, `CHANNEL_COLLECTION_ATTEMPT`와 주문 신선도 테이블을
사용하므로 스키마 생성 없이 HMR 전용 SELECT 계정의 조회 권한만 확인한다.

## 6. API와 웹 실행

터미널 1에서 API를 실행한다.

```powershell
apps/api/.venv/Scripts/python.exe -m uvicorn monitoring_api.main:app `
  --app-dir apps/api/src --host 127.0.0.1 --port 8000
```

터미널 2에서 웹을 실행한다.

```powershell
npm run dev --workspace=@collection-monitoring/web
```

브라우저에서 `http://localhost:5173`을 연다. 개발 서버 Origin이 달라지면
`MONITORING_CORS_ORIGINS`도 정확히 같은 Origin으로 바꾸고 API를 다시 시작한다.
와일드카드 Origin은 사용하지 않는다.

## 7. 안전한 로컬 확인

먼저 DB와 무관한 liveness만 확인한다.

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health/live
```

예상 응답은 `status`가 `ok`인 JSON이다. 이 결과는 DB 준비 완료를 뜻하지 않는다.

전용 연결 문자열이 명시적으로 설정된 경우에만 다음 SELECT-only smoke를 한다.

```powershell
curl.exe --fail-with-body http://127.0.0.1:8000/health/ready
curl.exe --fail-with-body http://127.0.0.1:8000/api/v1/monitoring/collectors
curl.exe --fail-with-body "http://127.0.0.1:8000/api/v1/monitoring/runs?page_size=5"
```

예상 결과는 readiness 200, 설정된 `fcdaum`/`hmr` 항목의 `ready: true`, 그리고
collectors/runs의 200 JSON 응답이다. 감사 이력이 아직 없으면 `items`가 빈
배열일 수 있으며 그 자체는 DB 장애가 아니다.

전용 연결 문자열이 없다면 실제 DB smoke를 수행하지 않는다. 정확한 차단 상태는
다음과 같다.

```text
GET /health/ready -> 503
{"status":"unavailable","items":[],"errors":[{"collector_id":"configuration","code":"SOURCE_UNAVAILABLE","message":"등록된 모니터링 데이터 소스가 없습니다."}]}
```

이때 collectors는 `items: []`, `errors: []`인 200, runs는 추가로 `total: 0`인
200을 반환하지만 이는 실제 DB를 검증한 결과가 아니다. 테스트 fixture나 mock
결과도 실제 smoke라고 기록하지 않는다.

## 8. 로컬 검증 명령

```powershell
apps/api/.venv/Scripts/python.exe -m pytest apps/api/tests -p no:cacheprovider
npm test
npm run typecheck
npm run lint
npm run build
```

검증과 smoke 중에도 수집 스크립트, DDL, INSERT, UPDATE, DELETE, MERGE를 호출하지
않는다.
