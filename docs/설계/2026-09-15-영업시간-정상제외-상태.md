# 영업시간 정상 제외 상태 적용

## 판정 기준

- `INVALID_PLACE`: 수집기가 업체 없음 또는 요청 업체와 다른 페이지를 확인한 경우. 폐점 확정과는 구분한다.
- `HOURS_NOT_PROVIDED`: 수집기가 영업시간 미등록으로 판단한 경우.
- 두 상태는 매장별 사유를 남기고 업무 DB 반영에서 제외한다. 기존 영업시간 및 실패 메타데이터를 갱신하지 않는다.
- dry-run 및 apply 단계에서 두 상태만으로 실행 실패를 만들지 않는다. 실패 재시도 목록에서도 제외한다.
- 다른 수집 오류, DB 오류, 검토 필요 판정은 유지한다. 과거 `NO_HOURS`는 원인 확인 없이 정상 제외로 재분류하지 않는다.
- 안전 대상은 기존 `NEW_STORE`, `UPDATED`, `UNCHANGED`만 유지한다. 정상 제외를 안전 반영 대상으로 추가하지 않는다.
- 감사 이력은 제외 사유별 매장 묶음을 분리한다. 시도 상태는 SUCCESS이며 error_category에 정제된 제외 사유를 기록한다. 프론트엔드는 기존 표시 기능을 사용한다.

## 배포

1. 대시보드 API의 `apps/api/src/monitoring_api/adapters/naver_store_hours.py`를 반영하고 API를 재시작한다. 신규 사유 허용을 먼저 적용한다.
2. 로컬 `C:/workspace/naver_crawling/scripts/python`의 다음 다섯 파일을 서버 크롤러의 `scripts/python`에 교체한다.
   - `naver_store_hours_browser_automation.py`
   - `naver_store_hours_chunk_checkpoint.py`
   - `naver_store_hours_chunk_runner.py`
   - `naver_store_hours_monitoring.py`
   - `naver_store_hours_manual_review_report.py`
3. 실행 중인 크롤러가 없는 시점에 교체한다. 다음 실행의 summary, checkpoint, 감사 이력을 대조한다.

DDL 변경 및 기존 실행 이력 수정은 없다. 서버 실행과 운영 DB 쓰기는 이번 작업에서 수행하지 않았다.
